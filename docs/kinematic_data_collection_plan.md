# 数据采集机制更换方案：磁吸物理 → 运动学轨迹驱动

日期：2026-09-18。状态：**规划，未改代码**。
决策：采用 **A 方案（运动学轨迹驱动，关闭物理，直接设定位姿）**；磁吸物理代码**保留但默认停用**。

前置文档：[跨越内直角与 U 肋诊断](magnetic_robot_crossing_plan.md)（说明为什么物理路线走不通）、[巡检定位方案](weld_inspection_localization_plan.md)（结构先验与视觉算法目标）。

---

## 1. 任务目标

**目的**：采集小车运动过程中的 **RGB 与深度图像数据**，用于后续焊缝巡检定位算法的开发与验证。

**明确约定**（由用户指定）：

- **不要求小车遵守真实物理规律**；
- 需要的是**运动拓扑连通**：顶板/底板平面 ↔ U 肋，以及顶板/底板 ↔ 正向板（跨内 90° 直角），并能返回；
- 现有磁吸物理机制**无法满足**该要求。

## 2. 为什么换机制

### 2.1 物理路线存在量级不匹配（不可通过调参解决）

实测几何（`bottom_plane.stl` / `top_plane.stl`，已套用世界变换）：

| 几何项 | 实测值 |
|---|---|
| 通道底面 | `z = 0.0100 m`，通道宽 0.48 m |
| U 肋顶面 | `z = 0.2600 m`，肋顶宽 0.16 m |
| **U 肋高** | **0.2500 m** |
| 肋侧壁倾角 | 53.0° 离水平 |
| 根部转角 | 90° 内直角，无倒角 |

| 越障目标 | 所需轮半径（`μ=0.8` 实算） | 相对当前轮径 63 mm |
|---|---|---|
| 70 mm 尖角台阶 | `R ≥ 300–400 mm`（轮径 600–800 mm） | **10–13 倍** |
| 250 mm 肋高 | 更大，且受 `h < R/2` 约束 | 更大 |

当前整车**轴距仅 70 mm**。轮径 600 mm 配 70 mm 轴距在几何上不成立。故在现有机构尺寸下，"板面运动到 U 肋上"与"跨 90° 直角到正向板"**不存在可行的物理方案**——与扭矩、摩擦、磁吸模型、控制策略均无关。

扭矩侧的独立证据：把限幅从 0.8 N·m 提到 ∞，可翻越的尖角高度仅从 3.61 mm 升到 6.20 mm（摩擦封顶），几何绝对上限 15.75 mm。

### 2.2 物理仿真的产出与任务需求错配

| 任务真正需要 | 物理仿真提供 |
|---|---|
| 相机位姿确定、可重复 | ✗ 接触求解抖动、滑移，每次不同 |
| 精确真值标注（通道号、里程、当前承载面） | ✗ 只能事后反推，含滑移误差 |
| 运动拓扑受控（保证 A 面 → B 面） | ✗ 靠力平衡"碰巧"成功 |
| 采集吞吐 | ✗ 复杂网格实时因子 < 1 |

### 2.3 运动学模式下跨面过渡降级为插值问题

承载面平面方程与法向已知时，跨面过渡就是**在已知面上插值位姿**：无需力平衡、无后翻、无打滑、无棱角处磁吸法向失效。

## 3. 架构决策

| | A. 运动学轨迹（**选定**） | B. 引导力混合 | C. 继续优化磁吸物理 |
|---|---|---|---|
| 做法 | 关物理，每步设 `base_link` pose | 保留物理，插件算目标 pose 施加修正力 | 改棱角磁吸 + 大轮径 + 力控 |
| 跨面过渡 | 直接可达 | 可达但与 200 N 磁吸拔河 | 机构尺寸不允许 |
| 可重复性 | 完全确定 | 中等 | 差 |
| 采集速度 | 快 | 中 | 慢 |
| 真值标注 | 路径自带，精确 | 需反推 | 需反推 |
| 改动量 | 新增轨迹插件，现有代码基本不动 | 中等 | 大，且大概率仍失败 |

选 **A**。将来若需要物理真实感做算法鲁棒性测试，再考虑 B。

## 4. 详细设计

### 4.1 离线结构先验（阶段 A 产出）

把桥体解析成**可行面图**。该产物同时是 [巡检定位方案](weld_inspection_localization_plan.md) §3 要求的结构先验，一次投入两处复用。

```
节点 = 承载面
  字段: surface_id, 平面方程, 法向, 外边界多边形, 面内切向基, 类型
  类型: channel_floor | rib_web_L | rib_web_R | rib_top | front_panel | inner_wall

边 = 运动原语
  字段: 起面, 终面, 二面角, 长度/角度, 进出位姿, 最小清障宽度
```

来源：`gazebo_bridge/models/bridge/meshes/*.stl`（15 组），按现有 `(x,y,z)_world = 0.001·(X,−Z,Y)_CAD` 变换。

注意：**不要**把所有 STL 三角剖分边当作真实棱线；同一光滑曲面上的剖分边无几何意义。需按平面聚类后求交线。

### 4.2 位姿序列生成

```
轨迹 = [seg_0, seg_1, ..., seg_n]
seg  = { 起点 pose, 终点 pose, 插值方式, 时长, surface_id, 原语类型 }
```

姿态由几何直接构造，保证相机始终"看向行进方向、贴合当前承载面"：

```
forward = 路径切向在面内的投影，归一化
up      = 当前承载面法向
R       = [right, forward, up] 正交化
```

这样 RGB/Depth 视锥朝向随承载面自动切换——正是巡检定位算法需要的数据形态。

### 5.3 停用（保留代码，默认不加载）

| 文件 | 处置 |
|---|---|
| `src/MagneticAdhesion.cc` | 从生成的 world 中移除 `<plugin>`，源码保留 |
| `src/RobotDriveController.cc` | 同上，由 `TrajectoryDriver.cc` 取代 |
| `src/SteeringLimitMonitor.cc` | 同上（无真实转向自由度） |
| `config/drive.yaml` | 保留但不再注入插件 |

**重要**：停用只改"生成 world 时是否挂载插件"，**不删源码、不动 `validation/` 下的既有验证报告**。方案书 [磁吸小车建模方案](magnetic_robot_gazebo_sim_plan.md) 与 29 项物理验证结论**继续有效**，只是不再是数据采集链路的一环。

用户在 §2.1 实验中对 `drive.yaml` 与 `RobotDriveController.cc` 的改动（`rpm: 30.0`、`wheel_torque: 6.4`、校验放宽到 `rpm<=30`）保留为对照记录。

### 5.4 插件实现要点

- `Configure`：读 YAML，缓存每面平面/法向；建立 `sim::Entity` 到 `base_link` 的映射。
- `PreUpdate`：`t = simTime`，定位当前段，算 `pose(t)`，设世界位姿。
- 轮子自转与前轮转角**纯显示驱动**（按里程线性映射到关节角），使 Gazebo 观感与 `/joint_states` 连续；不参与动力学。
- 物理关闭方式：从生成 world 移除 physics 插件；小车保留为动态模型但每步被外部设定位姿（等价于可行且最简单）。
- 段间姿态插值用**四元数球面插值**，避免跨面处欧拉角跳变（尤其 90° 直角过渡）。

## 6. 数据采集链路（必须先解决吞吐）

### 6.1 现状约束

| 模式 | 内容 | 数据量 |
|---|---|---|
| `record_mode:=rgb`（当前默认） | **只有 RGB 视频** | ~15 MB/min |
| `record_mode:=full` | RGB + **原始深度 32FC1** + CameraInfo + TF + 时钟 | **~3 GB/min** |

**当前默认的 `rgb` 模式不保存深度。** 采集深度必须走 `full`。

### 6.2 取舍建议

| 措施 | 效果 | 代价 |
|---|---|---|
| `camera.yaml` 的 `fps: 30 → 10` | 数据量降至 ~1 GB/min | 时间分辨率下降；车速 9.9 cm/s 时 10 fps 仍对应 9.9 mm 空间间隔 |
| 分段录制（直线段用 `rgb`，棱角/端部/换道切 `full`） | 总体积大幅下降 | 实现与流程复杂度上升 |
| 不录点云（现状已如此） | 点云可由深度+内参离线重建 | 无 |

**预算参考**：10 分钟 `full` 采集 ≈ 30 GB；覆盖三道正向板 + 多通道蛇形遍历可能达数百 GB。定方案前需先确认磁盘预算。

## 7. 必须配的清障与可见性检查

运动学模式**不做碰撞检查**，轨迹写错会直接穿进钢板并采到废图。这是 A 方案唯一的真实风险。

`scripts/check_trajectory.py` 需沿轨迹逐步计算相机/辅助杆/车体扫掠体与桥体网格的最小距离，并输出：

- 每段最小间隙（负值即穿模，直接判失败）；
- 每姿态下的**有效深度像素比例**（受 `depth_near` 限制，见 §8）；
- 相机自遮挡（视锥被横板/车轮/相机壳体挡住）检查；
- 连续退化区间长度（为巡检状态机提供依据）。

该工具与 [巡检定位方案](weld_inspection_localization_plan.md) §4 要求的"安装和动作可见性扫描"是同一个东西，一次投入两处复用。

## 8. 两个必须提前处理的传感器约束

### 8.1 深度近裁剪 0.45 m 会吃掉焊缝

`bridge_d415_sim/config/camera.yaml` 当前 `depth_near: 0.45`。相机到钢板距离小于 0.45 m 时**深度直接无效**，而焊缝巡检恰需贴近观察。

D415 在 `640×360` 下的标称 Min-Z 为 **0.24 m**，存在下调空间。但**不能只改参数**——需与**安装姿态**（相机朝承载面倾斜）联合设计，并用 §7 的可见性扫描验证有效深度比例。[巡检定位方案](weld_inspection_localization_plan.md) §4 已明确此陷阱。

### 8.2 当前模型没有真实焊缝几何

现有桥梁为统一材质的结构网格，**无独立焊道对象**。RGB 中看到的只是结构交线。

因此本方案产出的数据：

- ✅ 适合验证**几何定位**（平面、结构线、端部、通道编号）与**深度管线**；
- ❌ **不能**用于宣称焊缝识别性能。

补足需要单独的"带焊道、涂装、光照随机变化的仿真资产"，建议单独立项。

## 9. 执行顺序与验收

| 阶段 | 工作 | 通过标准 |
|---|---|---|
| A | 离线结构先验 → `structure_prior.json` | 面/法向/边界/二面角与 STL 量测一致 |
| B | 单通道纵向运动学行驶（单面直线原语） | 相机位姿正确、TF 可查、`full` 模式录到深度 |
| C | 跨面过渡原语（板面↔肋壁↔肋顶，含 90° 直角） | 过渡段无穿模，姿态四元数连续无跳变 |
| D | 清障/可见性扫描器（§7） | 每条轨迹报最小间隙与有效深度比例 |
| E | 多通道蛇形遍历 + 正向板换道 | 覆盖区间有记录，可重复复现 |
| F | 录制策略定型（帧率/分段/存储预算） | 单次采集体积可控，数据可回放 |

**阶段 B 之前不再进行任何物理侧调参**（扭矩、摩擦、磁吸模型），包括已完成的 `30 rpm / 6.4 N·m` 实验——该组参数仅作对照记录保留。

## 10. 未决问题

2. 是否需要在运动学模式下也保留"物理感"（如轮子随坡度俯仰的视觉细节），还是纯几何位姿即可。
3. 顶板侧 U 肋与底板侧 U 肋朝向相反，通道内是否构成窄缝，需单独量测顶板下侧净空。
4. 相机安装俯仰角是否作为可配置项（关系到 §8.1 的有效深度）。
5. 是否需要为"焊缝外观"单独构建仿真资产（独立立项）。
