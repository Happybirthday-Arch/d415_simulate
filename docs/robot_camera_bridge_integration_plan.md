# 小车、D415 相机与钢桥联合仿真方案书

日期：2026-09-16。状态：首版已实施；辅助杆按最新要求改为 3 cm。启动方式与实测结果见 [联合仿真说明](../d415_sim_ws/src/bridge_robot_sim/README.md)，下文中的拟定内容保留为设计依据，实施差异见文末。

目标：将现有磁吸小车、D415 相机和钢桥组合到同一个仿真场景；相机通过长 3 cm 的辅助杆固定在前轮附近的车身横板上，前端沿车体 X 方向与横板前缘齐平；使用键盘 WASD 控制小车，直行轮轴目标转速为 15 rpm，同时观察 RGB、深度图和点云。新增仅录制 RGB 画面的轻量模式，作为联合仿真的默认录制方式；深度继续实时生成和显示，但该模式不保存深度数据。

**1．现有基础与本次范围**

本方案根据当前仓库的模型、配置、生成脚本和相机 Xacro 编写，沿用项目现有的 ROS 2 Humble、Gazebo Sim Fortress 和 DART 物理后端。

| 模块 | 当前基础 | 本次需要增加 |
|---|---|---|
| 钢桥 | `gazebo_bridge/models/bridge`，已有显示和碰撞网格 | 在联合世界中复用，与磁吸查询使用一致的放置变换 |
| 小车 | `gazebo_robot`，前后各一个轮子、前轮转向，已有碰撞、惯量、磁吸和限位 | 正式轮速控制、转向控制、状态反馈 |
| 相机 | `d415_sim_ws`，已有 D415 外形、RGB/Depth、点云、录制和回放 | 改为车载 3 cm 辅助杆安装，接入动态 TF，新增仅 RGB 视频录制 |
| 操作界面 | 已有 Gazebo 和 RViz2 | 增加能够识别按下、松开和组合键的键盘控制窗口 |

当前小车质量预算为 2.70 kg，轮径 63 mm，零位轴距约 70 mm；有效吸附时每轮磁力为 200 N。转向外部边界为 ±15°，物理停止位置为 ±14.9°。

首版完成桥内底板行驶、组合转向、停车和随车图像观察，并在独立斜面、侧壁、倒挂面上回归附着及停车能力。跨越 90° 棱边、自动避障、SLAM、焊缝识别和路径规划留到后续阶段；现有磁吸能力不等于已经验证跨面行驶能力。

**2．相机安装方案**

安装解释：将“前轮处的车身横板”对应到 `robot_chassis` 上方的横板。辅助杆底端固定到横板顶面，沿车体 +Z 方向竖直伸出 30 mm，顶端固定相机底部安装位置。杆长 3 cm 暂定义为横板顶面到相机底部安装面的有效支撑高度；首版不另加有厚度的转接板，后续若增加，应明确计入高度。

相机镜头朝车头，长边沿车身左右方向，默认横向居中，俯仰角为 0°。刚性连接关系为 `base_link → camera_support_link → d415_bottom_screw_frame`，两处均使用固定关节。相机与辅助杆随车身运动，前轮转向时保持相对车身姿态不变。辅助杆截面暂按直径 10 mm 的实心圆杆建模，作为可配置的工程假设；直径不是用户指定值，实施时需核验固定区域。

车体坐标约定沿用原模型：X 向前、Y 向左、Z 向上。这里的“上”是相对车身，侧壁或倒挂时仍沿用同一局部坐标。

对当前派生 STL 的测量结果如下，数值均相对 `base_link`，单位为 mm：

| 几何项 | 当前测量值或来源 |
|---|---|
| 上横板 X 范围 | −52～+52 |
| 上横板 Y 范围 | −74～+74 |
| 上横板厚度范围 | Z=51～57 |
| 横板安装面 | Z=57 |
| 辅助杆有效长度 | 30 |
| 辅助杆顶端／相机底部安装面 | Z=87 |
| 横板前缘 | X=52 |
| 相机名义外形 | 前后深度 20.05、左右宽度 99、高度 23 |
| 相机可见网格相对底部安装坐标系的 X 范围 | 约 −10.18～+9.87 |

相机前端齐平以**外壳可见前表面**为基准，不以光学坐标原点或底部安装孔为基准。由此得到首版安装初值：

```yaml
# 位置单位 m，角度单位 rad；xyz 均相对各自 parent。
# 这是方案初值，实施时还需进行几何和碰撞验收。
camera_support:
  parent: base_link
  child: camera_support_link
  xyz: [0.04213, 0.0, 0.05700]  # 杆坐标原点位于底端
  rpy: [0.0, 0.0, 0.0]
  length: 0.030
  diameter: 0.010  # 暂定，可配置
  geometry_center: [0.0, 0.0, 0.015]
camera_mount:
  parent: camera_support_link
  child: d415_bottom_screw_frame
  xyz: [0.0, 0.0, 0.03000]
  rpy: [0.0, 0.0, 0.0]
```

相机底部安装坐标系相对 `base_link` 的位置更新为 `[42.13, 0, 87.00] mm`。相机可见前端仍位于 X≈52 mm，底面升至 Z≈87 mm，顶部约为 Z=110 mm；相机后部向横板内部投影延伸约 20.05 mm，横向两侧投影名义余量各约 24.5 mm。按当前底板出生位姿估算，相机主体中心高度约为世界 Z=140.1 mm，实际值随物理接触收敛略有变化。

```text
侧视示意（非比例图）                         车头 +X →

                          ┌──────────┐
                          │   D415   │ → 镜头朝前
相机底面 Z=87 mm         └────┬─────┘ X=52 mm
                               │     ⋮
                               │     ⋮ 辅助杆长 30 mm
                               │     ⋮
横板顶面 Z=57 mm  ──────────────┴─────┤ X=52 mm
                                     前端与前缘在 X 方向齐平
                           前轮位于横板下方
```

装配需要完成以下检查：

1. 以横板实际三角面核对辅助杆底端固定区域，并核对杆顶与相机底部安装位置，不能仅凭整体包围盒认定安装成立；记录安装孔、局部开孔及支撑面的位置关系。首版固定关节代表刚性安装，螺钉可以不细建。
2. 核对前端平齐误差，建议不超过 0.2 mm；给出侧视、俯视和正视截图。
3. 扫描前轮从 −15° 到 +15° 的完整转向范围，检查相机及辅助杆与前轮、前电机、转向机构的最小间隙；按升高后的整车包络检查桥内障碍物净空。
4. 检查 RGB 和 Depth 视锥是否被横板、车轮或相机壳体遮挡；安装角度后续若调整，需要重新计算齐平位置。
5. 保留有效碰撞体。当前官方相机 box 碰撞体前端比其可见网格约多出 0.155 mm，实施时明确记录该差异，必要时只在组合模型中调整碰撞体局部位置以贴合外壳。

质量处理沿用此前“整车 2.70 kg 包含等效附件”的预算约定：暂采用本地相机模型的 0.072 kg；辅助杆按上述实心圆杆和密度 2700 kg/m³ 的铝材等效假设，质量约 0.00636 kg。从原有车架/附件等效质量中划出两者共约 0.07836 kg，放到各自实际位置，更新整车质心与惯量。辅助杆惯量按圆柱计算，质量和截面均可配置；支撑加高后的重心和抗倾覆表现需要重新验收。若以后明确 2.70 kg 是不含相机及辅助杆的裸车实测质量，则总质量相应增加，当前假设下约为 2.77836 kg。

官方相机 Xacro 已注明其惯量不可靠，组合仿真中应按外壳几何和暂定质量计算等效惯量；质量预算调整也要重算被扣减部分的惯量。相机参考坐标系可以无质量，但最终参与动力学的刚体必须具有有效质量和惯量。

**3．15 rpm 的定义与运动控制**

本方案暂将用户指定的 15 rpm 理解为**轮轴输出转速**，不是减速器前电机转速。若后续提供的是电机转速和减速比，需要重新换算。

按轮径 D=0.063 m、无滑移直行估算：

```text
轮轴角速度 ω = 15 × 2π / 60 = 1.5708 rad/s
车体线速度 v = π × 0.063 × 15 / 60 = 0.04948 m/s
             ≈ 4.95 cm/s ≈ 2.97 m/min
```

15 rpm 是稳定行驶目标；启动、减速、换向过程采用平滑过渡。实际速度还受接触、滑移和控制误差影响，需要同时记录轮速与车体位移。

小车是前轮转向结构，控制分成两个轮轴速度闭环和一个转向位置闭环。利用关节力矩驱动物理模型，在仿真步中读取实际状态、更新控制量；控制插件采用 Fortress 的物理步前控制、步后反馈方式，具体接口依据 [Gazebo Fortress System 插件文档](https://gazebosim.org/api/gazebo/6/createsystemplugins.html)。

| 参数 | 首版建议值 | 说明 |
|---|---:|---|
| 直行目标轮速 | ±15 rpm | 两轮同向；正号对应车体向前，实施时验证关节方向 |
| 单轮目标速度上限 | 15 rpm | 转弯时同样执行 |
| 转向目标 | ±14° | 留出到 ±14.9° 物理停止位置的裕量 |
| 轮速变化率 | 30 rpm/s | 从静止到 15 rpm 约 0.5 s，待调试 |
| 转向变化率 | 30°/s | 从中位到 14° 约 0.47 s，待调试 |
| 单轮驱动力矩上限 | 初值 0.8 N·m | 需通过启动、制动、斜面及侧壁试验确认 |
| 转向力矩上限 | 实施值 5 N·m | 0.5 N·m 初值带载转向不足；已验证调整后的闭环与原有限位 |
| 物理步长 | 1 ms | 沿用现有物理配置 |
| 键盘命令发布频率 | 50 Hz，墙钟时间 | 不依赖键盘系统重复输入频率 |
| 命令失联阈值 | 0.25 s，单调墙钟 | 超时进入停车状态 |

上述控制参数均为调试初值，不表示已通过实测或对应真实电机参数。闭环应有力矩饱和和积分抗饱和，不能用持续修改车体位姿来模拟行驶。

转弯时前后轮行驶路径不同，不能简单地始终强制两轮都等于 15 rpm。首版根据实际转向角、轮轴位置和转向轴偏置计算两轮目标速度，再等比例缩放，使任一轮目标绝对值不超过 15 rpm。现有前轮相对转向轴约有 9 mm 偏置，不能把 70 mm 轴距的理想自行车公式直接当成精确控制模型。

用于量级预估，忽略偏置时有 `n_rear ≈ n_front × cos(δ)`；在 14° 转向、前轮 15 rpm 时，后轮约为 14.55 rpm。直行两轮均为 15 rpm，弯道车速因此略低。最终以实际几何计算和物理试验为准。

停车时采用零速闭环并根据需要接入有限力矩的位置保持。仅将驱动力矩设为零会让侧壁或斜面上的自由轮继续滚动，不能视为有效驻车。换向时先减速到零，再向相反方向加速。

**4．WASD 操作约定**

使用独立的小型键盘控制窗口接收按键事件；窗口获得焦点后操作，持续按住才持续发出运动请求。界面显示当前按键、目标/实际轮速、转角、连接状态和停车状态。

| 按键 | 动作 |
|---|---|
| `W` | 向车头方向行驶，未按 A/D 时前轮回中 |
| `S` | 倒车，未按 A/D 时前轮回中 |
| `A` | 前轮向车体左侧转到目标角；单独按下不主动行驶 |
| `D` | 前轮向车体右侧转到目标角；单独按下不主动行驶 |
| `W+A` / `W+D` | 前进并左转 / 右转 |
| `S+A` / `S+D` | 倒车并保持前轮左打 / 右打；车头偏航方向与前进时相反 |
| 松开 `W/S` | 平滑减速到零并保持停车 |
| 松开 `A/D` | 前轮按设定速率回中 |
| `W+S` | 前后输入冲突，停车 |
| `A+D` | 左右输入冲突，转向目标回中 |
| `Space` | 立即进入制动请求并锁定运动输入；实际停车受力矩及接触约束 |
| `Enter` | 所有运动键已松开后解除制动锁定，不立即恢复行驶 |

A/D 表示前轮相对车体的方向，不代表横向平移或原地旋转。侧壁、倒挂工况仍采用同样的车体局部方向约定。

失去窗口焦点、窗口关闭或控制链路中断时，清空按键状态并请求停车；Gazebo 插件另设独立的命令超时保护。窗口必须提供真实的 key-down/key-up 状态，不能用普通终端只收到字符的方式冒充松键检测。

暂停、世界重置和恢复运行时清空旧命令及控制积分状态；恢复后需要先松开按键再重新按下。超时使用墙钟，动力学控制使用仿真时间；仿真暂停时无法产生物理制动，恢复后的首个有效物理步必须先检查命令有效性。

**5．联合仿真与相机数据链路**

建立一个联合启动入口，只启动一个 Gazebo 世界、一辆组合小车和一套 `/clock`。建议在现有 `d415_sim_ws/src/` 下新增 `bridge_robot_sim` 集成包，复用 `gazebo_robot` 的模型生成结果和物理插件，以及 `bridge_d415_sim` 的相机宏、图像支持脚本和录制工具。

组合模型以小车 SDF 为物理基础，加入辅助杆、两处固定连接、相机外形、碰撞和传感器。由脚本从相机宏生成并合入相机部分，同时生成匹配的 ROS 描述；固定关节归并后必须核对传感器实际位姿、质量和 frame 名称。集成生成器同时输出装配参数、变换和来源记录，避免 SDF 与 ROS TF 各自维护一套安装数值。

沿用此前辅助支撑安装的思路，将独立测试支架改为长 30 mm 的车载辅助杆。旧的独立测试模型 `d415_test_mount`、100 mm 高支架几何、`static=true` 和 `world → camera_mount` 固定位姿不进入联合模型。

```text
键盘控制窗口
    → ROS 2 命令接口 /robot/drive_command
    → ROS/Gazebo 命令桥接
    → 轮速与转向控制插件
    → 前轮、后轮、转向关节

Gazebo 实际位姿与关节状态 → ROS 动态 TF / 状态显示
D415 RGB/Depth → 既有桥接与 CameraInfo 处理 → RViz2 实时显示
D415 RGB → 仅 RGB 录制器 → RGB 视频（默认）
完整数据链路 → rosbag2 录制器（仅 full 模式启用）
```

实际命令使用 `geometry_msgs/Vector3` 与 `ignition.msgs.Vector3d` 桥接：x 表示油门 −1～1，y 表示转向 −1～1，z>0.5 表示制动；控制插件内部完成轮速和转角映射。命令使用 `/robot/drive_command`，实际反馈使用 `/joint_states`，命令值不作为实际状态发布。

联合世界沿用桥梁绕 X 轴 +90° 的放置方式，以及磁吸插件使用的钢桥网格和模型名。初始位置沿用桥内底板中间通道：车体参考位置约 `[0, -1.5, 0.0416] m`，车头朝世界 +Y；加装后重新确认出生间隙和稳定接触。

相机输出继续使用当前配置：

| 输出 | 首版设置 |
|---|---|
| RGB / Depth 分辨率 | 640 × 360 |
| 目标采样频率 | 30 Hz，按仿真时间统计 |
| 深度范围 | 0.45～3.0 m |
| 原始深度 | `32FC1`，单位 m |
| 可视化 | RGB、Depth preview、XYZ 点云、车体与相机坐标系 |

现有深度近裁剪为 0.45 m，因此紧贴车前或车底的钢板不一定有有效深度。首版沿用该设置，并在图像中检查实际可见区域；后续如果要检测很近的焊缝，需要单独调整工作距离、安装姿态或传感器模型，不能把裁剪参数缩小就等同于真实相机近距离能力提高。

坐标链采用：

```text
world
└── base_link                         动态：Gazebo 实际车体位姿
    ├── rear_wheel_link              动态：实际关节状态
    ├── front_steering_link          动态：实际转向角
    │   └── front_wheel_link         动态：实际关节状态
    └── camera_support_link         固定：辅助杆底端相对车身
        └── d415_bottom_screw_frame  固定：相对辅助杆底端 +Z 30 mm
            └── d415_link
                ├── d415_color_frame → d415_color_optical_frame
                └── d415_depth_frame → d415_depth_optical_frame
```

`world → base_link` 首版直接使用仿真真值，标注为 ground truth，不包装为定位算法结果。每条 TF 只能有一个发布者；车体真值位姿、关节状态和图像使用一致的仿真时基，并在图像时间戳处检查 TF 是否可查询。相机原有 RGB/Depth 外参、独立内参和 CameraInfo 修正逻辑继续复用，但须重新验收固定关节归并后的效果。

桥箱照明先沿用当前世界灯光，行驶路径上检查明暗变化；若有明显暗区，再增加固定在车体上的可见光补光并计入配置。Gazebo 自由观察视角与 D415 成像分别管理。

录制与传感器运行分开配置，新增 `record_mode` 参数。三个模式下 RGB、深度图和点云均继续实时生成并可在 RViz2 中查看；区别只在于写入磁盘的内容。

| 模式 | 保存内容 | 使用场景 |
|---|---|---|
| `rgb`（默认） | 仅 RGB 压缩视频及少量录制说明、帧时间索引 | 日常观察，减少磁盘占用 |
| `full` | RGB、原始 Depth、两路 CameraInfo、TF、时钟、关节状态、驾驶命令和真值位姿的 rosbag2，附运行配置 | 明确需要数据分析和完整回放时手动选择 |
| `off` | 不录制 | 只运行和查看仿真 |

`rgb` 模式直接订阅 `/d415/color/image_raw` 并编码为 `rgb.mp4`（拟采用 H.264），不先生成原始图像 bag 再导出视频。该模式不启动全量 rosbag2 录制，不保存深度原图、深度预览、点云、CameraInfo、TF 或运动状态流；实时深度显示及其依赖节点保持运行。已有相机启动入口中的默认录制器必须由联合启动显式关闭，避免后台重复写入大包。

建议保留很小的 `recording.json` 和 `rgb_timestamps.csv`：记录分辨率、编码设置、帧数、每帧仿真时间戳及掉帧情况，不包含其他传感器流。按图像时间戳组织视频时间轴，使仿真运行较慢时，回看仍反映仿真速度；暂停期间不重复录制静止帧，时间重置时切分新片段。编码队列设置容量上限，过载时统计丢帧，避免录制拖住控制或深度显示；退出时完成编码器收尾，确保 MP4 可正常播放。

首版建议目标码率约 2 Mbit/s，可配置；按该码率估算视频约 15 MB/min，实际大小取决于编码输出。相比之下，640×360、30 fps 的未压缩 RGB 像素负载约 1.24 GB/min，尚未计入其他话题和容器开销。这里只是容量预算，交付时以实测文件大小为准。

`rgb` 模式产物使用普通视频播放器查看，仅凭 RGB 视频无法恢复深度或完整 ROS 场景；`full` 模式沿用并扩展 rosbag2 回放，回放时不启动驾驶控制节点。30 Hz 是仿真目标，墙钟帧率取决于实时因子，须分别报告。

联合启动已支持 `record_mode:=rgb|full|off`，默认 `rgb`。

**6．实施顺序与验收**

| 阶段 | 主要工作 | 验收要求 |
|---|---|---|
| A：组合装配 | 确认安装面，生成 30 mm 辅助杆、相机固定连接与惯量 | 有效支撑高度 30 mm；前端平齐误差 ≤0.2 mm；完整转向扫描无新增穿插；保存三视图及外参 |
| B：静态联合加载 | 同一世界加载桥、车、相机 | 无重复模型或时钟；相机随车；接触和磁吸正常；质量预算一致 |
| C：直行闭环 | 平钢板上正反向与加减速 | 稳态每轮 15±0.3 rpm；稳定直行 10 s 约移动 0.495 m，位移误差目标 ≤5% |
| D：转向和组合键 | 左右转弯、倒车转向、按键冲突 | 转向方向正确；两轮目标均 ≤15 rpm；目标角稳态误差 ≤0.5°；实际转角始终不超过 ±15° |
| E：停止与异常 | 松键、失焦、断开、Space、暂停和重置 | 超时 ≤0.25 s 后撤销行驶请求；普通停车从撤销请求起目标 0.7 s 内轮速降到 0.3 rpm 以下；恢复不执行旧命令 |
| F：移动成像 | 直行、转弯时查看 RGB/Depth/点云 | 图像随位姿正确变化；光学坐标正确；图像时间戳处可查询 TF；已知平面距离检查通过 |
| G：附着与驻车回归 | 独立斜面、竖直面、倒挂面 | 加装辅助杆及相机后每类保持 60 s 仿真时间；无异常脱离；停车后 10 s 沿面漂移目标 ≤2 mm，记录饱和情况 |
| H：钢桥与录制 | 桥内行驶并分别验证 rgb/full/off | rgb 视频可播放且无深度或全量 bag 落盘，录制时深度持续显示；full 可回放图像和轨迹；off 无录制产物；报告文件大小、实时因子、实际采样率和丢帧 |

以上是拟定的首版验收目标，测试结果必须如实报告；不满足时先排查几何、控制、接触或算力瓶颈，再说明需要调整的参数及依据。位移验收从轮速稳定后计时，不把加速段算成匀速段。转弯检查轮速补偿与滑移，不能只看视觉上是否转弯。

**8．首版实施结果与设计调整**

- 辅助杆长度更新为 **30 mm**，相机底部安装点为 `[42.13, 0, 87.00] mm`，前端仍为 X=52 mm。杆底 709 个网格采样点均落在实际横板顶面；新增支撑与转向部件的 Z 区间至少相隔约 6 mm，绕 Z 转向不改变该分离关系。
- 为避免固定刚体的多余约束，相机和杆的显示、碰撞、传感器及等效惯量合入 `base_link`，ROS 中保留辅助杆、相机和光学坐标的完整固定 TF。装配与控制参数分别位于 `bridge_robot_sim/config/assembly.yaml`、`drive.yaml`，生成文件写入 `d415_sim_ws/runtime/robot_*/`。
- 驾驶命令实际采用 `geometry_msgs/Vector3` 与 `ignition.msgs.Vector3d`：x 为油门输入，y 为转向输入，z 为制动标志；实际关节状态仍为 `/joint_states`。驱动与反馈话题分开，并已通过本机双向桥接验证。
- 0.5 N·m 的初始转向力矩不足以克服强磁吸下的接触阻力，实测后改为 **5 N·m 限幅**，位置闭环采用 PID。独立钢板测试左右稳态角约 +13.96° / −13.95°，最大绝对角约 14.14°，保留原机械限位和独立监测。
- 独立钢板与实际钢桥的直行速度分别约 0.04949 m/s，前进、倒退、左右转向、松键停车、失联停车及制动已验证。斜面、侧壁和倒挂面各完成 61 s 仿真驻车，保持每轮 200 N 有效吸附。
- 实际钢桥中 RGB、深度、预览、点云和图像时刻 TF 均通过检查。仅 RGB 模式生成 H.264 视频及小型索引/统计，不写深度数据包；full 模式已核对保存的话题和关闭结果，off 模式用于 GUI 验收。
- 键盘窗口以真实按下/松开事件处理组合键，失焦停车；短暂的渲染减速不会自行当作松键。控制器的暂停、重置或失联状态会清除旧输入，并要求中立命令重新启用。
- Fortress 的传感器调度在世界时间重置后可能暂时停更，直到新仿真时间追上重置前的下一帧时刻。录制器通过只读 `/clock` 检测回退并分段，不把时钟流写入视频目录；要立即重新开始完整成像，建议退出后重新启动仿真。

测试报告位于 [integration](../gazebo_robot/validation/integration/)，实际运行说明以联合仿真 README 为准。可用一条 `d415_sim_ws/run_robot.sh` 启动钢桥、小车、3 cm 相机辅助杆、键盘窗口、RViz2 和默认 RGB 视频录制。
